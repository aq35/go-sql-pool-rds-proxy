# pat-timeout — db.r6g.large

**問い**: クエリごとのタイムアウトを短くすると、限界付近の負荷で、接続の作り直しとクエリの積み残しが連鎖して、処理量(goodput)が落ちるか。クライアントが切った後も、Aurora でクエリは走り続けるか

**仮説**: 限界の 80%(rps=300)では、タイムアウトが短くても、ほぼ影響がない。限界の 120%(rps=460)では、タイムアウトが短いほど、タイムアウトと新規接続が増え、goodput が下がる。クライアントが切断した後も、Aurora 側ではクエリが走り続ける(aurora_running_max がクライアントの同時数より多い)。

**読み方**: rps ごとに、timeout なし(0)と各タイムアウトを比べる。見る列: goodput_qps、timeouts、new_connections、aurora_running_max / avg、Aurora の CPU。goodput が timeout なしより低く、new_connections が増えていれば、連鎖が起きている。
